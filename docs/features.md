## v1 — 내 폰에서 매일 쓰는 데까지

### 1. 재료 등록: 사진 (AI 스캔)

냉장고 안이든 장 본 것이든 찍으면, **사진 위에 물체마다 박스와 이름을 띄우고** 아래에 목록을 보여 준다.
뭔지 모르는 물체(불투명한 상자, 반찬통, 검은 봉지)는 `?`로 표시하고, 목록에서 사용자가 이름을 적는다.

```
┌──────────────────────┐
│ ┌─────┐   ┌───┐      │   초록  바나나      확실
│ │바나나│   │ ? │      │   노랑  두유?       확인 필요
│ └─────┘   └───┘      │   회색  ?           모름 → 이름 입력
│      ┌──────┐        │
│      │ 두유? │        │
│      └──────┘        │
└──────────────────────┘
 [✓] 바나나   3개  냉장  D-5
 [✓] 두유     1팩  냉장  2026-11-20   ← 확인 필요
 [ ] ?  [이게 뭐예요?____]  ← 이름을 적거나 끄기 전엔 저장 안 됨
```

| 기능 | 시안 | 서버 | 메모 |
|---|---|---|---|
| 촬영 / 앨범에서 선택 | O | – | expo-image-picker. 사진 방향(EXIF)을 바로잡아서 보내야 박스가 맞는다 |
| 분석 중 화면 | O | `POST /recognition` | 실제 응답 시간 확인 필요 |
| **사진 위에 박스·이름 표시** | **X** | `boxes` (0~1 비율) | Gemini의 `[ymin, xmin, ymax, xmax]` 0~1000을 서버가 바꿔 준다 |
| **모르는 물체는 `?` → 사용자가 이름 입력** | **X** | `name` null + `description` | 이름을 적거나 항목을 꺼야 저장 가능 |
| 박스를 누르면 목록의 그 항목으로 (반대도) | **X** | – | |
| 결과 확인: 항목 끄기, 이름 수정, 수량 ± | O | – | |
| 확신 낮은 항목 경고 | O (%) | `confidence` high/low | 결정 3 |
| 유통기한 확인·수정 | **X** | `expiryDate`, `shelfLifeDays` | 시안에 추가 필요 |
| 보관 위치 선택 (냉장/냉동/실온) | **X** | `storage` | 시안에 추가 필요 |
| 이미 등록된 재료 표시 | **X** | **X** | 냉장고를 다시 찍으면 같은 재료가 또 잡힌다. v1은 이름이 같은 재고가 있으면 "이미 있음"으로 표시하고 기본으로 꺼 둔다 |
| 선택한 n개 저장 | O | `POST /items` | |

**서버 응답 (11/13 반영)**: 항목마다 `boxes`, 모르면 `null`인 `name`, `description`, `category`, `emoji`. 형식은 [README의 API](../README.md#api).

**나중에 (v2)**: 찍기 전 카메라 화면에 실시간으로 이름 띄우기. Gemini는 한 장에 몇 초 걸리고 사용량 한도가 있어서 실시간은 안 된다.
폰 안에서 도는 모델(YOLO → CoreML)이 필요하다 → `ml/` 실험이 여기 쓰인다.

## 시안과 기획이 다른 점 (결정 필요)

1. ~~**스캔 대상**~~ — **정함 (11/13)**: 냉장고 안이든 장 본 것이든 둘 다 찍을 수 있게 한다.
   가려진 물건은 못 잡지만, 잡힌 건 사진 위에 표시되니 사용자가 바로 안다. 모르는 건 `?`로 받는다.
   중복은 "이미 있음" 표시로 막는다 (1번 표).
2. **"사진은 분석 후 자동으로 삭제돼요"** — 서버는 사진을 저장하지 않지만, Gemini 무료 등급은 보낸 데이터를 구글이 학습에 쓸 수 있다.
   → 이 문구는 쓸 수 없다. 문구를 바꾸거나, 이 약속이 필요하면 유료 등급으로.
3. **AI 확신도 %** — 모델이 스스로 말하는 퍼센트는 근거 있는 숫자가 아니다.
   → 숫자 대신 high/low로 "확인 필요"만 표시하는 걸 추천.
4. ~~**카테고리**~~ — **정함 (11/13)**: 시안의 4개(달걀이 유제품, 고기·소스 자리 없음) 대신 11개.

   | 키 | 이름 | 기본 이모지 |
   |---|---|---|
   | `vegetable` | 채소 | 🥬 |
   | `fruit` | 과일 | 🍎 |
   | `meat_egg` | 육류·계란 | 🥩 |
   | `seafood` | 수산 | 🐟 |
   | `dairy` | 유제품 | 🥛 |
   | `tofu_processed` | 두부·가공 (햄·어묵) | 🫘 |
   | `side_dish` | 반찬·김치 | 🥢 |
   | `sauce` | 소스·양념 | 🧂 |
   | `beverage` | 음료 | 🧃 |
   | `ready_meal` | 간편식 (냉동·즉석·라면) | 🍱 |
   | `other` | 기타 | 📦 |

5. ~~**이모지**~~ — **정함 (11/13)**: 모델이 재료마다 고르고(🍌), 못 고르면 위 표의 카테고리 기본 이모지.
6. **기술** — 시안은 웹(React + Tailwind + shadcn), 앱은 React Native.
   코드는 그대로 못 쓰고 디자인(색·배치·문구)만 가져온다. NativeWind를 쓰면 Tailwind 클래스는 비슷하게 쓸 수 있다.
